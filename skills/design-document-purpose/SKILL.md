# 資料の目的と論点を設計する

## 入力・出力・必要な能力

- 入力: 資料の依頼、想定読者、元情報、指定された形式や制約。既存資料があれば利用する。
- 出力: 読み手の終了動作、資料の主目的、中心の問いまたは伝える内容、根拠に対応した構成案。未確定事項は明示する。
- 必要な能力: 提供された文章の読解と構成案の作成。重要な不足情報がある場合は依頼者への確認。ファイル読取や成果物生成は、入力・指定形式に応じて利用可能な能力を確認する。利用できない場合は読める元情報を求めるか、本文・構成案を渡して制約を伝える。

## 読み手の終了動作から設計する

本文やスライドを作り始める前に、依頼から「誰に、読んだ後どうしてほしいか」を短く言語化する。

| 主目的 | 作成前に定めること | 構成の軸 |
| --- | --- | --- |
| 知ってもらう | 読み手が何を理解すれば完了か | 要点と、その理解に必要な説明・根拠 |
| 決裁を得る | 誰に、何について Yes / No を求めるか | 決裁事項、提案、判断に必要な根拠・費用・リスク・代替案 |
| 議論する | 相手と一緒に答えを出したい疑問文 | 中心の問い、選択肢や比較軸、分かっていること・未確定事項 |

複数の目的が混ざる場合は、会議や資料の最後に求める行動を主目的にし、情報共有などの補助部分を組み込む。この分類は実務上の道具として使い、依頼された形式や用途を無理に三択へ押し込まない。

目的が成果物の形を変えるのに判断できない場合だけ、一問確認する。例: 「読み手には、理解してもらう、承認してもらう、一緒に考えてもらう、のどれを求めていますか？」既に分かることは聞き直さない。

## 議論の中心を具体化する

「相談したい」「意見がほしい」などの依頼では、何を一緒に考えるのかを確認する。依頼に明確な論点があればそれを言語化し、不明なら「今回、相手と一緒に答えを出したい問いは何ですか？」と尋ねる。広すぎる問いは、対象・決める範囲・期限・比較軸のうち不足する一点を次の質問で絞る。

「海外事業について」のような話題を、「最初にどの工程を自社で担うべきか？」のように議論できる問いへ変える。単なる情報共有の依頼に、決定や議論を追加しない。

図が役立つ場合は、参加者が指さして選択肢や違いを話せる中心図を構成案に含める。例えば工程図に、内製候補・外注候補・未判断の箇所を置く。比較表や文章で十分ならそれを使う。未確定の答えを決定済みとして書かない。

## 構成案を仕上げる

読み手・終了動作・主目的を短く示し、それに必要な見出しと各部分の要点・根拠を並べる。枚数や見出しの数は内容と依頼に合わせる。根拠の不足は調査事項として残す。

読み手が「何を理解するか」「何を承認するか」「何を議論するか」を資料から判断でき、各部分がその目的に寄与すれば構成案は完了。目的を左右する確認への回答が得られない間は、仮定と未確定事項を示した草案に留める。

資料本体まで依頼されていれば、この構成から続けて作成する。指定形式の生成には、実行環境のスキル探索で利用可能な能力を確認し、適切なものを使う。このスキル単体では特定の生成ツールや追加スキルを必須にしない。

## 知見の由来

由来を確認・更新するときは、[問いの質と資料3分類](https://github.com/omitsuhashi/hermes-life/blob/eeca4248e12909cb5f4300f9eb4c92a926a0d266/wiki/concepts/question-quality-and-three-document-types.md) と、そこから参照される本人の入力・字幕を読む。通常の実行時に取得する必要はない。

3分類と中心図の考え方は動画由来。作成前に目的を捉え、議論の論点を問い直す期待は本人の明示入力に由来する。上記の構成・確認手順は、それらを再利用するための整理であり、動画の主張全体や個別事例を本人の普遍的な規則として扱うものではない。
