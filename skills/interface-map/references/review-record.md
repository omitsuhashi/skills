# 指摘の対象と版を記録する

モデルの保存済みソースと、その版から描いた図・exportを編集前に保存する。Gitのcommitだけでは未commitのモデル変更を含まない場合がある。実ソースのhashや保存したsnapshotなど、実際の表示元を特定できる版を使う。

## 対応づける情報

ノードとエッジの永続IDはモデル全体で一意にする。既存IDを優先し、新規に必要なら`N1`、`E1`などの短いIDを割り当てる。モデル形式にmetadataがなければ小さな対応表で保持する。

| 対象 | 編集前のモデルへ照合する情報 |
| --- | --- |
| ノード | 永続ID、完全修飾名などのモデル参照、選択時の名前・契約、viewと版 |
| エッジ | 永続ID、source/targetの永続ID、呼出／データの種類、選択時の操作・payload、viewと版 |
| 図・欠けた接続 | view、関係するノードID、自由文、版 |

collapsed viewの一本の線が複数の関係を表す場合は、該当する元のエッジ集合を確認する。一本に決め打ちしない。表示上のIDとモデルの対応を持ち、短いIDをエッジラベルに含めると、選択テキストだけのフィードバックでも対象を特定しやすい。

描画順やラベルの一致だけで曖昧なエッジを選ばない。対象版が手元になければ取得・復元できるか調べ、取得できなければ対象確認を返す。現在の図を過去の図の代わりに使わない。

## 最小の記録例

既存のレビュー記録があればその形式を使う。なければ、モデルの横やタスクの成果物に小さなJSON等で必要な情報を残す。次は記入例であり、新しい実行基盤や固定ファイル名を要求しない。

```json
{
  "modelRevision": "snapshot-r1",
  "comments": [
    {
      "id": "C1",
      "view": "processing",
      "target": {"type": "edge", "reviewId": "E3"},
      "before": {
        "source": "N4",
        "target": "N7",
        "kind": "call",
        "label": "judge(ParsedRequest)"
      },
      "text": "渡す情報を明確にしたい",
      "status": "open"
    }
  ]
}
```

改名はIDを維持する。移動は旧参照と新参照の対応も記録し、親と外部接続への影響を見る。削除は元の対象と本文を残し、削除が指摘への回答なのか、再対応づけが必要なのかを示す。削除だけで`resolved`にしない。

## 修正と再確認

変更後の版、何を変えたか、対象ID、表示先、検証したことを記録に追加する。新しいUIセッションを開く場合にも元の指摘との対応を持ち越す。途中で別の編集が入ったら、受け取った指摘の版との違いを照合してから適用する。

| 状態 | 意味 |
| --- | --- |
| `open` | 対象を確認中、または対応待ち |
| `changed` | モデルを変更した段階。検証未完了も含む |
| `awaiting-human-check` | 検証結果と更新図を返した段階。変更不要という回答も理由を添えて返す |
| `resolved` | 人がその指摘の解消を確認した段階 |

コメントのピンは補助表示であり、この記録の代替にしない。自動テストや別エージェントの検証で`resolved`へ進めない。ユーザーが特定の指摘だけ確認した場合は、その対象だけを更新する。
