# 設計ドキュメントの配置

既存の設計文書があれば、役割を対応づけて正本を更新する。Issueなどが正本の場合は、以下の役割をその中の見出しやリンクに割り当てる。保存が依頼範囲に含まれなければ、配置案と本文を提示する。

設計文書もクリーンアーキテクチャの責務に沿って配置する。設計ドキュメントフォルダを作る場合は、次を基本構成とし、ルートの名前・場所は対象プロジェクトの規約に合わせる。内容のある文書だけを作り、空のフォルダや雛形一式は作らない。

```text
docs/design/
  overview.md
  domain/
    rules.md
  application/
    usecases/
      UC-01-submit-application.md
    ports/
      application-store.md
  adapters/
    http.md
    database.md
```

- `overview.md` に目的・対象範囲、ユースケース一覧、全体像の Mermaid 図、各詳細文書へのリンクを置く。
- `domain/` に業務の用語・ルール・状態変化を置く。具体的な DB・API・フレームワークの事情は接続資料で扱う。
- `application/usecases/` ではユースケースごとに識別子と業務名を付ける。目的・前提・入出力・正常系と重要な失敗系の Mermaid 図・検証案をまとめ、利用する業務ルールとポートへリンクする。
- `application/ports/` にユースケース側が所有する接続契約を置き、操作・データ・結果・失敗時の意味と保証を定める。
- `adapters/` に入口・出口の接続方式、形式変換、認証・通信・保存の詳細を置き、対応するユースケースと内側のポートへリンクする。

実装コードの配置は、コードの責務と技術の制約から決める。
