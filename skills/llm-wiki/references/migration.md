# Migrating an existing index/log root

Use only when changing an existing root's convention, within the user's authority.
Preserve raw, ownership, drafts, citations, contradictions, and existing note and
heading identities. Continue the old convention until regression passes.

1. Record representative questions and required evidence pages before cutover.
   Include terminology differences, overview, stale-current claims, partial
   replacement/conflicts, missing/invalid metadata, drafts, orphans, unsaved new
   pages, and corrections found only in history.
2. Try the catalog in a task workspace. Reconcile every old index registration
   against every wiki file. Transfer useful summaries, unique aliases, global
   applicability cautions, and index-only knowledge into the relevant pages;
   classify derivable/redundant information rather than copying keyword lists.
   Link previously index-only non-Markdown evidence from explanatory pages.
3. Connect history-only corrections from affected knowledge to the exact history
   entry or integrate the correction with its provenance. Keep log bytes and
   heading identities; append one cutover notice explaining that normal appends
   end and how to search the retained history. Do not split it into event files.
4. Retry the questions with generated catalog, body search, and links. Require
   the same necessary evidence and correct handling of stale/partial guidance.
   Exercise listing/read errors, parser/generator fallback, and filter coverage.
   Test separate page additions on independent branches when Git is in use;
   after integration each appears once without shared management-file edits.
   Check same-concept additions for semantic duplicates despite clean merging.
5. After regression passes and no unique information is unexplained, switch the
   skill/local schema, callers, and checks together. Delete `index.md` completely;
   leave no stub, renamed fixed inventory, or tracked archive copy. Redirect real
   links in maintained pages to verified destinations. Preserve immutable raw
   and old log quotations; document their narrow historical-index exception and
   Git-history lookup in the local schema, not a general broken-link exemption.
6. During integration of old branches, recover meaningful index/log changes into
   affected pages manually; do not reintroduce shared files through auto-merge.
   If discovery regresses after cutover, temporarily use full catalogs generated
   from current pages. Do not restore the old index as current knowledge.

Keep runnable mechanical checks for enumeration, metadata and parser degradation,
read failures, drafts, rename/addition, order, and no-write workflow outcomes.
Record semantic question/evidence results separately; structure tests do not
prove retrieval quality. A failed pre-cutover regression postpones migration.
